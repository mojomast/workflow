01 The shipping path
01
Idea

Kyle describes the outcome in plain words, often with a reference — a video, a repo or a screenshot.

02
Plan & spec

An agent reads current docs and source, then writes a PLAN.md or SPEC.md with numbered tasks, defaults and open questions.

  • Contracts first (Slice 0)
  • Non-overlapping file leases
  • Dependent work in waves
  • One integration PR

Kyle approves a scoped plan: it names what is allowed and what is not.

03
Orchestrator

A Grok Bot coordinates the work. MR.INDIA is the general orchestrator. Specialists: Hermes Forge and Hermes Plugin Builder. Project bots: Cheese, BABA BOOEY, DOLAN, hammy. Codex sessions contribute research, review and creative packs. Hermes and Pi run as agents in Orbit. Briefs are self-contained: hard rules first, approved and not-approved scope, measurable acceptance, and the evidence to bring back.

04a
DeepSeek bees

Cua sandboxes on Kyle’s Windows PC, reached through the Orbit launcher. The bulk of leased coding since early November. Briefs are self-contained. Up to six bees at once. Heavy work stays on the PC, not the box.

04b
Executor subagents

Short-lived Grok Bot workers on the box: plan folds, screenshot sets, film plans, merges and documentation.

04c
Cursor cloud agents

Opus, Sonnet, Gemini or Grok. Used for contract slices, audits, hard features and one coherent PR. Last resort — only when Kyle asks.

04d
Asset pipelines

GenerateImage, Google Colab with a CU cap, ComfyUI, Remotion on CPU (zero CU), and HyperFrames. Game assets are original, with provenance. Hermes and EOH shots are always dark mode. No slop‑style graphics.

05
Verify verify.sh

Lock; fast-forward the feature branch; reject any file outside assigned_files; run the task’s tests, then the suite, under nice and ionice; measure the schema budget; secret-scan; commit and push the feature branch only.

Worker claims are self-reported — only what verify reproduces counts.

06
Feature branch + PR

One integration PR from the feature branch to main, with a summary and a question card for Kyle.

07
Merge → tag → release

Each step needs its own yes. Merge style follows the repo.

08a
Deploy

moltussy-1, the public VPS, or GitHub Pages. Backup first; record the rollback. Restart only what is needed. Verify the real path.

08b
Nous catalog

YAML-only PR, full SHA, images pinned to it, at most six screenshots. Change requests: fix, patch release, repin, point-by-point reply.

08c
Demo, post, form

Demo under 90 seconds, 1080p30. X post drafted as a card; Kyle posts. Typeform filled to Submit; send only on yes.

02 Reproducible collaboration

Roles, not a required set of agents. The unit of progress is an accepted artifact with evidence. Existing publication and deployment gates still apply.

01

Define the outcome

Kyle sets the outcome and constraints. Restate them, read current sources, and name uncertainties.

02

Package

A versioned spec or HANDOFF.md: baseline, decisions, inputs, checks, return format.

03

Produce

Build the agreed slice. Preserve editable sources. Return the artifact plus RETURN.md evidence.

04

Review evidence

Check acceptance against the actual artifact. Reproduce consequential findings. Label checks passed, failed, not run, or blocked.

05

Revise or integrate

A specific correction returns to the package. Accepted work is integrated only within authorization.

06

Save the lesson

Record the resulting revision and a reusable lesson or template. It feeds back into research, skills and the next brief.

04 Infrastructure

Where the work runs. Private hosts and URLs are omitted. Ask before any deploy or restart. Back up first; deploy the approved tag; verify the real path; keep a recorded rollback.

The box

Shared Linux workspace for every Grok Bot. Orbit, coordinators, verify and git live here. Services are controlled with boxctl. Heavy work uses nice/ionice, or is sent to bees.

Kyle’s Windows PC

Docker Desktop and Cua. The bee launcher runs here. The model key stays on the PC. A launcher restart needs Kyle’s OK.

moltussy-1

Hermes test host. Dashboard and gateway run as user services; plugins are git checkouts. Every deploy records a backup and rollback.

Public VPS

nginx, Docker and systemd. Public sites and the Temple of Hermes BBS. Isolated TLS, one published app port, previous container kept until accepted.

GitHub

Repos, releases and Pages. Catalog work uses a fork branch. Secret-scan before every push. No force-push or history rewrite without a yes.

Google Colab

GPU runtimes for ComfyUI. Ask before any spend. Every run has a CU cap, is torn down afterwards, and has its spend logged.

05 Approval gates · only Kyle’s own words count
merge · tag · release · catalog PR, open or repin · deploy or restart (Orbit, moltussy-1, VPS, PC launcher) · upstream comments · X posts (Kyle posts himself) · form submits · GitHub Pages · Google Colab spend · deleting anything · force-push, branch deletion, history rewrite · Cursor cloud agents
A checklist, a sibling bot’s relay, or an ambiguous “go ahead” is not permission. Confirm relayed approvals with Kyle. Stop or hold means stop now — don’t restart until he asks.
06 Lessons that feed back
Contracts first, then leased parallel slices, then one integration PR.
Measure tool-schema cost on every change. Smoke-test on a real Hermes before tagging a review fix.
Keep evidence in new folders; never overwrite earlier sets. Secret-scan before every push.
Record every deploy’s backup path and rollback. Promote a correction only at its proper scope, into a skill or template.
