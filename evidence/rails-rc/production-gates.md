# Activation gates and limits

**Do not activate a fleet from the synthetic acceptance run.** The four PRs are review candidates. M1a's read path has a real launcher, transport, importer, authenticated client, browser, and CLI operating on a fixture. M1 requires real worker execution, a separately authenticated reviewer, human feedback, and a qualified RETURN at that job's exact revisions. M2 additionally requires the qualified performance surface and the supported retry contract. Neither milestone has a live sign-off.

| Capability | What the corrected implementation establishes | What the deployment owner must establish |
|---|---|---|
| Native RETURN | Frozen manifest shape and semantics, restored receiver-side verification, pinned sidecar bytes, and explicit pending decisions. A coordinator-recorded reviewer label cannot satisfy an independent review criterion. | Establish the protected verifier-to-receiver channel for production, stable generation/anchor access, authenticated reviewer identity and actual campaign evidence. The tested write-time receipt capture is a private fixture channel. |
| Worker origin | Enrollment and cursor/hash anchoring support authenticated, byte-preserving observations. The attachment refuses criterion attribution when the immutable lease lacks the original chain assignment. | The current production dispatcher has no authoritative job-to-worker-chain intent before posting the job. Bind the authorized control endpoint, worker, ledger, project, frozen contract and revision in the coordinator's pre-POST intent; carry that original assignment into its signed lease. Read enrollment, a mutable profile, or adopting an attempt after restart cannot supply this missing proof. This is an **implementation/integration prerequisite as well as a host authorization gate**. |
| Owner controls | Workspace-bound signed quality feedback is isolated from read transport; durable writer revalidation and replay have dedicated tests. Board runs are explicitly historical without a selected authenticated head. | Keep the legacy approval route unmounted. Retry/rewind requires a registered owner-capable consumer revalidating at claim and commit. No administrative capability follows from a successful browser read or a quality vote. |
| Recovery | Receipt, deduplication, conflict detection and process-interruption checks cover the recorded code paths. A contradictory origin halts that source, not all workers. | Test copied historical state with `python3 -B -m bundlebees_plugin.wave_compat --state-dir /path/to/copied-state`. No production snapshot was supplied. Reconcile unknown legacy waves; never overwrite them to obtain a pass. Verify a stable snapshot of all RETURN companions before use; individually atomic file replacements do not guarantee atomic multi-file publication or survival of physical power loss. |
| Benchmarks | Dataset, selectors, caps, receipt identity checks, warm sample counts, hardware and stream observations are recorded per run. | Distinguish retained-reader from authenticated HTTP pagination, and unindexed from indexed local attempts. The optional index is an offline maintenance operation, not a fleet startup migration. Default and indexed claims do not generalize to mixed imported ledgers, physical SSD, multiple clients or UI paint at 2,000 marks under simultaneous live load. |
| Windows | Hosted Windows tests exercise actual native code and local transport. The offline contract rehearsal refused an uncontracted brief and created zero attempts. | Complete the [worker-specific 13-step handoff](https://github.com/mojomast/workflow/blob/c61ff1c122ba649ea59ff7807cc8e671ed080b33/evidence/rails-rc/windows-canary.md). Supply a nonsecret authorization reference binding the one-bee, 1,800-second window, enrolled worker/coordinator/chain, exact contract, permitted interruption and operator. No model route or usage from a live canary has been observed. |

The [sequencing and rollback procedure](coordination.md#sequencing-and-rollback) applies after the engineering and human gates have passed. If code is rebased or squash-merged, check reachability of the canonical source pins, rebuild packages and rerun the tuple rather than copying these results forward. The rollback order reverses activation, preserves durable history and restores previously tested binaries/configuration.
