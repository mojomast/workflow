# Lessons and friction from the acdd-lint dogfood run

These are in order of how much they cost. Each one names who or what was at fault.

1. **Test references must be pytest JUnit ids (`file::Class::test`).** The L1 and L2 contracts named tests as `file::test`. bundlebees `tdd red` matches criteria against JUnit case ids, so it refused RED with `red_incomplete`, and wrote an `unrelated_failure` RED against the v1 hash. The coordinator re-froze both contracts as v2 with class-qualified ids. Scope and tests did not change. The bees had already been dispatched with v1, so they received a contract that differs only in its test-id strings. *Fix for the workflow:* `contract validate` should warn when a test reference cannot match any collected id. Contract templates should show `Class::` ids for unittest-style tests. The stale v1 RED stays in the evidence, and acdd-lint flags it, which is the intended behaviour.
2. **bundlebees' Orbit adapter cannot fetch Orbit patches.** Orbit's `local-workers` `get` returns only a result *ref*; the patch lives in the launcher's result file. `hermes bundlebees verify` therefore reported `no_result_yet` for a finished bee. The coordinator host wrapped the real client so that `result()` reads the launcher's result file on the box. Leases, contract checks, the sandbox, signing and pushes still ran through bundlebees. *Open:* either the adapter reads result refs, or Orbit returns the patch to an authorized caller.
3. **The workflow repo is not on the launcher allow-list.** Bees could only work in bundlebees, so the tool was built on a bundlebees branch and ported with `git am`. The ported commits have new hashes; both sets are listed in the README. *Needs Kyle:* adding `workflow` to the allow-list is a launcher config change.
4. **`bundlebees integrate` cannot integrate bundlebees itself.** The sandbox mounts the checkout at `/work`. bundlebees' own `tests/fakes.py` refuses to load the plugin unless the directory is named `bundlebees`, so 129 of 469 tests failed inside `integrate`, and the signed integration records say `integration_failed`. The same suite passes 469/0 outside the sandbox. Integration also runs only `testpaths = ["tests"]`, so the acdd-lint tests are never part of integration, and per-criterion results in the report go back to `not run`. *Open:* make `fakes.py` independent of the directory name, and have integrate also run the contract's `scope.test_files`.
5. **L1 and L2 have unsigned GREEN.** They were dispatched with the coordinator's `orch.py` (Orbit API), not `bundlebees_dispatch`, so there was no bundlebees lease, and `bundlebees verify` could not record GREEN. They were verified with the coordinator's `verify.sh` (JUnit, worktree at `source_rev`). L3 and L4 went through `bundlebees_dispatch` and have the full signed chain. Recording a lease afterwards would have faked authority, so it was not done.
6. **A brief told a bee it "may create" a file outside its lease.** L2 was told it could create an empty `acdd_lint/__init__.py` locally. The launcher took it into the patch, and the coordinator's scope check refused the patch. The coordinator dropped that one empty file, loudly (`DROP_EMPTY_OUT_OF_SCOPE=1`). *Fix:* never suggest out-of-lease scratch files. Give parallel slices a shared, already-committed package skeleton instead.
7. **The metrics are partly misleading.** `regressions_found: 258` is the integration-sandbox failure from item 4, counted twice; there were no regressions. `tokens_total: 0`, because the Orbit result's usage is not in the shape bundlebees reads. The launcher's per-attempt usage appears to be the last model step only. `first_pass_rate: 0.5` counts only the L3 and L4 attempts; all four bees passed on their first try. All are reported here as recorded.
8. **The evidence key is not `lease.key`.** bundlebees signs evidence with a key derived from the lease key. Pointing `--key-file` at `lease.key` makes every record `evidence_tampered`, which is correct but confusing. The acdd-lint README now says so.
9. **Same-second timestamps.** The reference demo writes several records in the same second. acdd-lint v0.1 broke ties by file name and reported a false `red_missing`. This was fixed test-first as slice L4 (phase order breaks ties). Stale REDs also no longer count as RED, a finding from the L3 review.
10. **Small ones:**
    - Failure messages in signed records keep absolute box paths (for example a venv path), because bundlebees' scrub does not shorten local paths.
    - `canonical()` in acdd-lint drops only `_path`, while bundlebees drops every `_`-prefixed key. These are equivalent for records on disk, but not identical.
    - The CLI re-parses `where` to split out the file. A structured `file` field from `check_history` would be cleaner.
