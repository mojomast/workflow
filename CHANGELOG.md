- Campaign report fixes: `pull_requests[].merge_order` is now defined as a 1..N ordinal position and `recommended_merge_order` as the open PR numbers in that position order, compared as an exact sequence instead of a set. The old set comparison refused a normal report whose first PR is `#2` in position 1 and accepted a reversed order (`#1` in position 1, `#2` in position 2, recommended `[2, 1]`). Each audit now carries `status: clean|findings|not_run`: a completed review with zero findings is representable without inventing an `AF-###` entry, while a review that did not run needs a reason, is disclosed in `known_limits`, and never counts as the audit that ran. Also: a `NOT RUN` criterion must be named in `not_run` by id, a passing `test` criterion cannot contradict a failed recorded run of the same command, a non-finite performance value or budget is refused (budget direction stays undefined by design), unknown fields are refused instead of silently dropped, and the schema now matches the validator on `ran_at` timestamps, empty optional strings, artifact evidence patterns and the PR state/position rule.

- [31 Campaign continuity](docs/31-campaign-continuity.md): reconstructs the six Jackpot pauses as coordinator-turn endings (not job failures), then defines the durable campaign checkpoint (`objective`, sealed authorization snapshot, phase, active workers, dependencies, last action, next action, wait/blocker, revision), restart reconciliation against the durable job, and the factory-driver scheduler that must be run by the host. It separates deterministic restart tests from the unrun live-host trial. The closeout validator is hardened against stale-head test runs, stale or missing head-bound acceptance evidence, placeholder/bare-label/absolute-path evidence, and audit findings without a stable id, one traceable disposition, a reason where rejected/deferred, or with a duplicate id.
- [30 Campaign closeout](docs/30-campaign-closeout.md), `rizzstack.campaign-report/1` ([schema](schemas/campaign-report.schema.json), [validator](tools/campaign_report.py)) and the [campaign report template](templates/CAMPAIGN-REPORT.md): the first Jackpot Syndicate campaign showed that 27/27 task rows did not mean product acceptance. The closeout separates implemented, integrated and accepted evidence; requires a command and revision for test PASS rows; requires evidence for every PASS and an image or recording for a visual PASS; records each audit finding with a stable id and exactly one of fixed, rejected or deferred (with a reason where required); allows NOT RUN only with a reason and known limits; and keeps the receiver decision pending. The validator refuses an agent-filled acceptance, a ready campaign with a failed suite or blocker, stale merge orders, task-count arithmetic that implies acceptance, and credentials/private paths. A `campaign-report` CI job runs the protocol tests; it is not added to branch protection by this change.
### Added

- [Rizzstack Rails specification](specs/rizzstack-rails-spec.md) and the draft [`rizzstack.rails/1` event contract](schemas/rails/event.schema.json) (workflow #40, merged at `9850efa`; specification-only — no implementation, deployment, acceptance or interface freeze): one reusable, hash-chained activity history for humans and orchestrators — inspect a job, attempt, campaign or session, understand agent/tool timing, locate verified acceptance evidence, record feedback, and request an authorized retry without changing history. The spec pins the four repos plus vibeline at inspected revisions and reuses their mechanics with named adaptations: SQLite reads in `mode=ro` with `query_only` (upstream ledger is a reader, not a writer), explicit parent IDs and latest-authoritative evidence instead of inferred prose children, no automatic raw prompt, reasoning-transcript, tool-argument or tool-output ingestion, SHA-256 hash integrity with its limits stated (integrity is not producer honesty, and a worker claim never becomes verified PASS because it appears in a chain), trace replication by authenticated pull over the existing launcher connection, and the action queue — not Rails — owning authorized intervention. The standard-library-only runtime originates at bundlebees `contrib/rizzstack_rails/` and is vendored deterministically into hyvv and Orbit `contrib/rizzstack_rails/`; Orbit vendors pristine vibeline sources with a SHA-256 manifest under `contrib/vibeline/`. Milestones M0 (schema freeze, source fixtures, provenance, the auth/queue attachment decision), M1a (earliest integrated vertical slice: worker fixture → worker ledger → existing HTTP → coordinator import → actual Orbit proxy → rail, and the same CLI query at exact event identity), M1 (one bounded real campaign) and M2 (full source coverage, viewport/heatmap/ghost feedback and export, safe retry request flow, bounded performance plus independent audit) sequence slices R00–R18 with per-slice acceptance commands; consumers wait for the reviewed contract freeze and the named input artifacts. The draft event schema carries the kinds `genesis`, `job.state`, `attempt.state`, `tool.start`, `tool.finish`, `verification.result` and `feedback.recorded` over synthetic chained examples (`schemas/rails/examples.json`); R01 owns the frozen kind-specific payloads, semantic validation and golden vectors before any dependent dispatch.

- Feature packets gain `rizzstack.feature-packet/2` ([25 Feature packet](docs/25-feature-packet.md), workflow #39): a descendant packet may declare one or more dependencies with no ceiling, while `/1` keeps exactly-one and refuses a wider packet as `packet_schema`, with the refusal naming `/2` as the upgrade — re-issue the intent packet under the new version instead of widening the old one. Admission is a separate gate: `feature_packet.admit(packet, accepted=...)` validates the packet and then refuses `dependency_not_accepted`, naming the first dependency that is still missing in declared order, so a multi-dependency feature integrates on top of accepted, merged work instead of racing it; self-dependencies and duplicate dependency ids are refused. The `/2` shape is derived from the enforced `/1` schema at validation time, so `schemas/feature-packet.schema.json` keeps its exact bytes, the pinned examples keep resolving byte for byte and this change triggers no repin; a coordinator whose validator predates `/2` refuses such a packet as `packet_version_unsupported` instead of silently accepting it.

- [29 Bee Landed](docs/29-bee-landed.md) (workflow #34): the terminal landing event `rizzstack.bee-landed/1` ([schema](schemas/bee-landed.schema.json), [validator](tools/bee_landed.py), [tests](tests/test_bee_landed.py)) — a CloudEvents 1.0 announcement that an attempt reached a terminal state under a named lease and backend. LANDED is not VERIFIED is not ACCEPTED: a producer may emit LANDED but the validator refuses any attempt, verification, acceptance, approval or decision claim, and `state` is limited to the three terminal states, so a landed `succeeded` event is evidence that the attempt ended, never that its output is correct.
