# Core audit follow-up — November 17, 2026

Local changes on the four revisions in the [initial audit](CORE-AUDIT-2026-11-17.md). No live state or account is needed for the test commands below.

### Workflow and the usage handoff

- The existing required `bee-ci/reference` gate now depends on both the reference job and the `feature-packet` job that owns the single full-suite sweep. Tested all 16 success/failure/cancelled/skipped combinations: only two successes pass. Ruleset names are unchanged.
- Fixed the envelope reader rejecting the collector's published `rizzstack.observability/snapshot/1` identifier. Mixed or contradictory versions are still rejected.
- Orbit emits list price as `cost_usd_list`, timestamps as `ts_end` / `ts_start`, and may supply a producer total at `usage_raw.total`. Workflow now recognizes these when aggregating; an observed total wins over estimating `input + output`. Missing cost stays unknown, and quota alerts use measured allowance, not per-request estimates. The [smoke test](test_core_usage_roundtrip.py) now covers the collector as well as producer, validator, outbox, ingestion and replay. Hyvv omits unsupported optional stop-reason prose before publishing the event.
- The collector now streams usage rows. On the same 10,000-row synthetic JSONL file with one model and repository, peak Python allocations inside `usage_section()` fell from **11,201 KiB to 28 KiB** (`tracemalloc`); the new result included the reported total and list price that the old collector missed. Memory can still grow with the number of distinct groups.
- The trial report renders missing metrics as `unknown`; M3/M4 score captured briefs and their pinned digests. The default fixtures yield M3 scores of 0/2, 0/2 and 2/2 for arms A/B/C, and no captured visual-task brief for M4. The default CLI still exits 1: the observed 46.7% cost reduction misses the registered 50% H1 threshold.
- Verification: Workflow root suite **1,022 passed, 4 skipped** (131 subtests passed); observability **54 passed**. From Workflow, `python3 -B contrib/core-review/test_core_usage_roundtrip.py` checks the four working trees: a real Hyvv export followed by coordinator replay produces one ledger row and one snapshot request, retaining the reported 18-token total and unknown cost. Collector regressions also cover interrupted ledger reads and invalid or out-of-range numeric observations.

### Hyvv: indexed tail reads

- At 100 and 1,000 retained events a one-row tail read opens **one** event payload, and repeat registration opens **zero**. At 1,000, the median tail call fell from 35.80 to 9.97 ms, and repeat registration from 35.04 to 10.05 ms (five warm Linux runs). Reads still enumerate directory metadata and validate the index to discover files published before a writer crashed. Returned hashes come from the bytes read.
- Added Windows byte-range locking and a Windows-safe filename for canonical event IDs; POSIX names and wire IDs are unchanged. The publisher fixture verifies stored bytes, hashes, cursor, replay, and duplicate suppression. Spawned processes also exercise competing publications and a crash between publication and registration. **99 focused tests passed on Linux**; the API contract ran 93 tests with 3 skipped and no failures. The fixtures are wired into targeted Windows CI; native execution is pending. The read benchmark above measures export and index registration, not the launcher's separate attempt-conflict check.
- The attempt-conflict check now propagates an outbox listing or file-read error instead of treating it as permission to publish a second terminal state. A regression simulates a temporarily unreadable event, restores access and confirms the contradiction is still refused. Six related suites passed after this change (86 tests plus 7 subtests).

### BundleBees: verification and compatibility

- With partial metering, metrics and the CLI show a known token-cost subtotal and the number of attempts with and without cost. In the audit fixture, two metered attempts total $0.70, a third has unknown cost, and the total and rate per accepted change stay unknown. A reported zero counts as metered; duplicate reports for one attempt do not double-count. With full coverage, retries and rejections contribute to spend and the denominator counts distinct accepted changes. Metrics and CLI tests: **46 passed, 1 skipped** (requires a strong sandbox).
- Runner and cached-receipt normalization previously coerced `false`, `0.5` and `"0"` into successful exit codes and discarded an explicit blocker. Both paths now retain the refusal. Four negative regressions failed before the change; all four pass afterwards.
- Before rollout, from the BundleBees checkout, set `COPIED_STATE` to a private offline copy and run `python3 -B -m bundlebees_plugin.wave_compat --state-dir "${COPIED_STATE:?}"`. It prints bounded counts and safe IDs, and exits nonzero on an incomplete scan or incompatible record. See `docs/doctor.md`, “Pre-rollout check”, in that checkout. No production records were supplied or inspected.
- Combined check across metrics, CLI, wave inspection, live/cached suite evidence, receipt reuse, revision, and RETURN: **115 passed, 1 skipped**.

### Orbit: approval journal and production boundary

- The isolated legacy route appends and fsyncs one history line before publishing its receipt without replacement. It still validates existing history. Non-ENOENT read failures, corrupt/partial records, and uncertain writes return 503; retries after a completed decision return 409 without changing history.
- The production `/api/approvals` route stays **disabled**. Legacy requests do not have a trusted workspace binding; Orbit owner authentication does not establish the human approval or signing format required by BundleBees. A real server fixture returned 404 on list, detail and decision for both owner and workspace-controller credentials. The legacy page explains where to review requests, with no API calls or decision controls. See `docs/SECURITY.md`, “Job approvals”, in the Orbit checkout.
